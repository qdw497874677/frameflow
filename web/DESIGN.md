# art-workspace 前端设计

前端是**单用户、家用、Tailscale 内网**可访问的挑片台。一句话目标：把一次拍摄的照片，从「几十上百张也许是废片」变成「打星的进修改后、待删的进回收站、其余进原始」，全程用键盘或拇指完成。

`web/` 里的所有代码都是**纯客户端**：不碰磁盘，只通过 `contracts/openapi.yaml` 的 HTTP API 说话（开发时默认走 mock 数据源）。真实磁盘由后端（`server/`）独占。

---

## 信息架构（IA）

左侧边栏常驻（移动端收成 Sheet），分两组：

- **工作区**：挑片（唯一有变焦舞台的页面）、回收站、归档、规则、设置
- **照片库**：多根目录 + 懒加载目录树（离线根灰显「未连接」）
- 边栏 footer：本次会话统计（⭐ / 🗑 / 未标）+ 撤销 / 重置

顶栏只有调用「目录上下文」的东西：当前页面标题 + 当前目录 + 触发侧边栏的按钮。统计不占顶栏（会让照片区域变矮）。

### 页面职责

| 页面 | 回答的问题 | 不该做的事 |
|---|---|---|
| 挑片 | 这一批里哪些是我要的？ | 不动磁盘、不做归档决策 |
| 回收站 | 我删掉的东西还在吗？ | 不在挑片页做真删（真删只能从这里发起） |
| 归档 | 选中的照片会去哪、搬走了没？ | 不直接改标记 |
| 规则 | 什么样的照片、按什么模板、去哪个目录？ | 规则编辑 UI 等 wayfinder 票 003 定稿 DSL |
| 设置 | 我有哪些根目录、系统连的是什么后端？ | 不是媒体库管理页，没有导入/同步 |

## 挑片：一份数据，两种焦距

「一个看」（卡片流）和「批量扫」（瀑布流网格）**不是两个页面，是同一个舞台的两个焦距**：数据、标记、当前照片、撤销栈全部共享，只有呈现方式不同。

切换走 `store.zoomTo(mode)`：先算出落点（去网格前先让后台那层滚到当前这张），再由 `web/src/app/FlightOverlay.tsx` 用手写的「飞行元素」把照片从旧形态带到新形态（`translate + scale`，0.38s，不动布局）。不做共享元素魔法（试过 framer-motion `layoutId`，跨层不交接），因为只有一张照片在飞，手写更可控。

关键约定：

- 两层（`Stage` 里的 Deck 与 Grid）**都常驻挂载**，各自 `bg-background`，靠 `z-10` / `z-0` 与透明度切换；隐藏层保持布局，才能被测量和滚动。
- 飞行期间源和目标各自把自己那张照片藏起来（`opacity: 0`），落地后由新那一层接手，避免「半透明重影」。
- 舞台尺寸靠 `ResizeObserver` + **callback ref**（`useState` 存元素）测；一次性 `useRef` + `[]` effect 会在首屏走空态分支时永久失效。

### 交互契约（挑片）

| 手势 / 按键 | 结果 |
|---|---|
| 右滑 | 加星（默认 1 星）；同时下压可连加到 5 星，每 95px 一颗，盖章显示 `LIKE ★★` |
| 左滑 | 待删（进待删集合，不是真删） |
| `1`–`5` / `0` | 直接给当前照片打 1–5 星 / 清星 |
| `→` `f` / `←` `x` / 空格 | 下一张（提交）/ 待删并下一张 / 跳过 |
| `Ctrl/⌘ + Z` | 撤销上一步（卡片从离开的方向飞回来） |
| 双击 / 右下角 | 放大到 2.5×，可滚轮/捏合/拖动，右下角小地图显示视口，再双击复位 |
| `Shift + ←/→` | 在一个看 / 批量扫之间变焦 |

**星级与待删互斥**（待删清星、打星取消待删），且以 **pair 为单位**（RAW+JPEG 是一个实体）——这两条由 `store` 的 `write()` 强制，任何 UI 入口都绕不过。

## 回收站

删除是**逻辑删除**：照片移进 `dir/.trash`（成对进出），列表里消失但可还原。挑片页只负责「标待删」，进回收站的动作在回收站页由人点一次（`把待删的 N 张移入回收站`），避免误触即丢。

- 还原：回到 `fromDir`（原目录）
- 真删 / 清空：**唯一**会真正删磁盘文件的入口，必须 `window.confirm`
- 空态给出下一步动作，而不是一句「暂无数据」

## 归档：先预演，再动手

归档分两步，这是不可协商的产品约定（也是后端的原子单位）：

1. **预演** `POST /archive/plan` —— 只计算：按启用的规则展开 `dest` 模板，得到每张照片的 `from → to`、冲突与总体积。前端**按目标目录分组**展示，并列出 `skipped` 的原因（`待删：先移入回收站` / `已经在目标目录` / `没有匹配的规则`）。
2. **执行** `POST /archive/apply` —— 按 planId 真正移动，成对原子；结果横幅报告搬了多少、失败哪些。

页面上下的三条硬规则：

- 有「待删」时，顶部横幅先劝你去回收站（待删的照片不会进归档）。
- `dest` 模板的变量是可见、可解释的：`{root} {project} {device} {kind} {variant} {date}`。
- mock 数据源也走完整流程（`planArchive` / `applyArchive` / `movedAway`），保证没有后端也能演练。

## 规则

一条规则 = **条件**（`match`: kind / minStars / del / camera）+ **目标模板**（`dest`）+ 冲突策略（`onConflict`）+ 是否成对（`pair`），页面用徽标把条件读成人话（`照片和视频` `≥ 3 星` `不含待删` `RAW+JPEG 成对`）。

规则的持久化形态是 YAML（`GET|PUT /rules`），**模板 DSL 由 wayfinder 票 003 定稿**；在那之前规则页只做「读 + 启停」，编辑 UI 留白并明说，不假装能编辑。

## 状态与数据流

```
UI 组件  ──调用──▶  store（唯一可写状态）  ──端口──▶  PhotoSource
   ▲                    │                              │
   └── useAppState ─────┘                     mock 实现 / http 实现（按 VITE_API_BASE）
```

- `web/src/core/store.ts` 是唯一可写状态：所有视图、标记、树、回收站、规则、归档计划都在这里；组件只读（`useAppState()`）并调动作。
- `web/src/api/source.ts` 是端口（`PhotoSource`）：mock 与 http 两个实现必须行为一致，**页面只认端口**。
- 标记写入 `saveMarks` 走 400ms 防抖；归档/回收站动作是显式命令（不防抖，且以 `busy` 防重复提交）。

## 视觉与组件

- **shadcn/ui（Radix）+ Tailwind v4**：所有界面组件来自 `web/src/components/ui/`，不改它们的内部实现，只在其上调样式；图标统一用 `lucide-react`。
- 颜色语义在 `web/src/index.css` 的 tokens 里，暗色为唯一主题：`primary` 金（星）、`destructive` 红（待删/真删）、`muted-foreground` 次要文字。
- 照片本体永远不叠 UI：状态靠细环（`ring-1` / 当前项 `ring-gold`）、角落小徽标与底部渐变文字条表达。
- 移动端优先：安全区用 `env(safe-area-inset-*)`，底部操作行不遮内容，侧边栏走 Sheet。
