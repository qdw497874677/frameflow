# art-workspace 前端设计

前端是**单用户、家用、Tailscale 内网**可访问的挑片台。一句话目标：把一次拍摄的照片，从「几十上百张也许是废片」变成「打星的留下、待删的进回收站」。

应用不动原片：文件夹由用户自己先整理好，应用只是把它**映射**成一个项目来浏览与标注（星级 / 待删）。

`web/` 里的所有代码都是**纯客户端**：不碰磁盘，只通过 `contracts/openapi.yaml` 的 HTTP API 说话（开发时默认走 mock 数据源）。真实磁盘由后端（`server/`）独占。

---

## 信息架构（IA）

左侧边栏常驻（移动端收成 Sheet），分两组：

- **工作区**：挑片（唯一有变焦舞台的页面）、任务、回收站、设置
- **照片库**：多根目录 + 懒加载目录树（离线根灰显「未连接」）
- 边栏 footer：本次会话统计（⭐ / 🗑 / 未标）+ 撤销 / 重置

顶栏只有调用「目录上下文」的东西：当前页面标题 + 当前目录 + 触发侧边栏的按钮。统计不占顶栏（会让照片区域变矮）。

### 页面职责

| 页面 | 回答的问题 | 不该做的事 |
|---|---|---|
| 挑片 | 这一批里哪些是我要的？ | 不动磁盘、不做任何搬动决策 |
| 任务 | 我派出去的事进行到哪了？回流对不对得上？ | 不是队列管理器，不建任务以外的调度（kind 由后端注册） |
| 回收站 | 我删掉的东西还在吗？ | 不在挑片页做真删（真删只能从这里发起） |
| 设置 | 我有哪些根目录、系统连的是什么后端？ | 不是媒体库管理页，没有导入/同步/导出 |

## 挑片：一份数据，两种焦距

「一个看」（卡片流）和「批量扫」（等高行网格）**不是两个页面，是同一个舞台的两个焦距**：数据、标记、当前照片、撤销栈全部共享，只有呈现方式不同。网格按**行优先**排（`buildRows` 先按目标高度把一行凑满再换行，末行左对齐不拉伸）：挑片是横向扫读，列优先的 CSS 多列布局会让人来回 zig-zag。

切换走 `store.zoomTo(mode)`：先算出落点（去网格前先让后台那层滚到当前这张），再由 `web/src/app/FlightOverlay.tsx` 用手写的「飞行元素」把照片从旧形态带到新形态（`translate + scale`，0.38s，不动布局）。不做共享元素魔法（试过 framer-motion `layoutId`，跨层不交接），因为只有一张照片在飞，手写更可控。

关键约定：

- 两层（`Stage` 里的 Deck 与 Grid）**都常驻挂载**，各自 `bg-background`，靠 `z-10` / `z-0` 与透明度切换；隐藏层保持布局，才能被测量和滚动。
- 飞行期间源和目标各自把自己那张照片藏起来（`opacity: 0`），落地后由新那一层接手，避免「半透明重影」。
- 舞台尺寸靠 `ResizeObserver` + **callback ref**（`useState` 存元素）测；一次性 `useRef` + `[]` effect 会在首屏走空态分支时永久失效。

### 交互契约（挑片）

| 手势 / 按键 | 结果 |
|---|---|
| 右滑 | 加星（默认 1 星）；同时下压可连加到 5 星，每 95px 一颗，盖章显示 `LIKE ★★` |
| 左滑 | 待删（进待删集合，不是真删） |
| `1`–`5` / `0` | 直接给当前照片打 1–5 星 / 清星 |
| `→` `f` / `←` `x` / 空格 | 下一张（提交）/ 待删并下一张 / 跳过 |
| `Ctrl/⌘ + Z` | 撤销上一步（卡片从离开的方向飞回来） |
| 双击 / 右下角 | 放大到 2.5×，可滚轮/捏合/拖动，右下角小地图显示视口，再双击复位 |
| `Shift + ←/→` | 在一个看 / 批量扫之间变焦 |

**星级与待删互斥**（待删清星、打星取消待删），且以 **pair 为单位**（RAW+JPEG 是一个实体）——这两条由 `store` 的 `write()` 强制，任何 UI 入口都绕不过。

看片台（网格/卡片里点「看片台」进）：`←/→` 翻张、`1`–`5`/`0`/`X` 与挑片同义、`Z`（或顶栏按钮）在「适应窗口」与 **1:1 预览** 之间切——看合焦用，点一下画面回到适应。1:1 用的是 2048 预览图（全分辨率端点还没做，见 tickets）。

## 回收站

删除是**逻辑删除**：照片移进 `dir/.trash`（成对进出），列表里消失但可还原。挑片页只负责「标待删」，进回收站的动作在回收站页由人点一次（`移入回收站 N`），避免误触即丢。

注意「待删」是 tag，文件还在原处；而挑片默认把待删藏起来 —— 所以顶栏有一个「待删 N」筛选（点一下只列待删，状态进 URL 的 `?sel=del`），回收站页也会单独问一次后端列出「**还留在原地的待删**」。不这么做的话，打过 tag 的照片会既不在挑片里、也不在回收站里，人就再也够不着它了（这是端到端测试跑出来的真 bug）。

- 还原：回到 `fromDir`（原目录）
- 真删 / 清空：**唯一**会真正删磁盘文件的入口，必须 `window.confirm`
- 空态给出下一步动作，而不是一句「暂无数据」

## 已移出的能力：归档与规则

v1 曾有一整套「归档规则引擎」：条件匹配 + `{root}/{project}/{device}/{kind}/{variant}` 目标模板 + 先预演再原子移动（规范见 `contracts/rules.md`，语义见 ADR 0002，历史决策 003）。**它已被移出本产品的路线**（用户 m01572：「文件夹我可以先整理好，只需要导入文件夹扫描所有照片进行标记就可以了」）：文件夹由用户自己先整理好，应用只负责映射、标注、删除。

留在这里的只有两条不变量：**应用不导入、不导出、不搬动照片**；原文件只会被写标记（星标 XMP）与回收站操作碰到。导出（把挑好的照片交到别的目录/工具）与外部批注推送推迟到后续（此处保留原设计的延期说明，不代表已实现）。

## 标注的来源与时间

每次实际发生变化（星 0→3、待删 否→是）都会记一条变更：`{ photoId, field, from, to, by, channel, at }`。
落盘的是**追加型** `marks.jsonl`（后端，前端 mock 存内存），XMP 仍只留最终状态；`by` 目前恒为 `me`、`channel` 恒为 `inapp`。
设置页可以看到最近 10 条（`GET /marks/history`）。

这不是审计洁癖：将来把一批照片推给飞书让同事打星时，回来的标注必须能和你本地改的合并 ——
没有「谁、什么时候、改了什么」，合并只能靠猜。详见 `docs/core-model.md` §3 不变量 6。

## 选择集（Selection）

「当前看到的是哪一批照片」是一个**可序列化的谓词**（`{kind, stars>=3, marked, camera, taken, folder, ids}`），
不是一串 id。它能在 URL 里表达（`?sel=stars>=3,marked`，深链可分享）、能存进任务（导出/推送的输入），
求值语义前后端一致（规范 `contracts/selection.md`，前端参考实现 `web/src/core/selection.ts`）。
端口上它取代了原来的枚举 `filter`（`all|starred|trash|unmarked`）—— 枚举长不大，加个条件就要改端口。

## 登录门（单用户）

后端 `password` 留空 = 不启用认证，前端直接进（本地开发的默认）。填了密码：前端 boot 时问 `GET /health`，得到两个独立的答案 ——
`authRequired`（后端要不要密码）与 `authenticated`（**这次请求带没带有效凭据**）。只有「要密码且没带凭据」才显示登录页。

两者必须分开：只问「要不要密码」的话，刚登录成功、接着又跑一次 boot 的人会因为那次探测没带 cookie 被踢回登录页（这是端到端测试跑出来的真 bug）。静态壳（`/`、`/assets/*`）不受认证门保护 —— 锁上的话浏览器连登录页都拿不到，只会看到 401 的 JSON；数据全在 `/api/` 后面。

密码换一个签名 cookie（30 天）；AI/CLI 用 `POST /api-tokens` 签发的 Bearer，外部批注人用 `?t=` 自认证链接 token（见 `docs/core-model.md` §11）。

## 任务与批注

任务层是「异步的动作」（[docs/core-model.md](../docs/core-model.md) §8）。界面上有两张脸：

- **任务页**（工作区 → 任务）：左列表（按状态筛）+ 右详情（进度、items 快照、产物链接、事件流水）。数据只来自 `GET /jobs`、`GET /jobs/{id}`、`GET /jobs/{id}/events?since=`：列表每 4s 刷、详情每 2.5s 用 `nextSince` 当游标**增量**拉（形状与将来的 SSE 一致，换传输不改界面）。手机先给列表，点进去才有详情（顶栏给返回）—— 一上来就顶到详情会让人不知道自己在哪。
- **批注页**（`/j?t=<范围 token>`）：给外部批注人的一页，**整页独立**于 App 外壳（`main.tsx` 按 pathname 分流，没有侧栏、目录树、管理入口），也不需要登录 —— 全部凭据就是 URL 里那条 token：缩略图 `<img>` 直接带 `?t=`（图像标签带不上自定义 header，所以凭据必须在 URL 里）。逐张给星级/待删，每点一下立刻回流 `POST /jobs/{id}/inbound`，`clientRef = <photoId>:<stars>:<del>` 让断网重发幂等；发不出去的进队列，顶部显示「N 条没发出去 + 重发」。刷新页面时从任务 items 读回自己已经标过的项。

入口在挑片页底部（「派发批注」）：**直接复用 store 里那份 Selection**（同一份谓词语义，前端不重写），补两件事 —— 绑当前项目（`project`）、选择集为空时用「眼前这批」的 id 清单；张数以服务端的 `mode:'plan'` 预演为准（先看再派）。apply 是异步的：`POST /jobs` 立刻回 `queued`，链接由 handler 落进 `artifacts`，所以对话框会盯着 `GET /jobs/{id}` 直到链接出现。

文案一律说「任务」，不说 job（[GLOSSARY.md](../GLOSSARY.md)）。撤销/取消按状态与 `reversible` 置灰，服务端的 409 中文原因直接显示给人看。
