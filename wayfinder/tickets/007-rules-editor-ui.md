## Question

规则 [DSL 已定义](../../contracts/rules.md)（YAML + `{token}` 模板、首条命中即停、条件 AND / 同字段数组 OR）。
现在要定的是：**人在屏幕上怎么改它**。

要摆平的取舍：

1. **表单还是文本**？纯表单（一条规则 = 一组下拉与输入框）永远写不出语法错误，但表达不了 `{date:YYYY-MM}` 这类模板的灵活；
   纯文本框（直接编辑 YAML）最自由，但把校验负担推给人。中间态是「表单为主 + 目标模板这一格给带变量提示的输入框」还是「双栏：左表单右 YAML 实时同步」？
2. **顺序怎么呈现**？首条命中即停意味着顺序就是语义，UI 必须能排序，而且不能自动重排。拖拽排序、上下箭头、还是列表 + 「这条不会被用到（被上面某条遮住）」的提示？
3. **命中预演**：编辑规则时能不能立刻看到「当前这批照片里，这条规则会命中几张、去哪个目录」？这是最能把「顺序」讲清楚的手段。
4. **别名表的编辑面**：`devices.yaml` 是独立文件（`ILCE-7M4 → A7M4`），放在规则页的侧栏、设置页、还是自动提议（扫到未知机型时问一句「这是你的哪台机器」）？
5. **错误呈现**：整份文件校验失败时（未知变量、非法值），是整页错误、还是定位到那一格？（决定后端返回什么形状的错误）。

产物：一张可点的原型（或两个形态差异明显的变体），能让人回答「我愿不愿意用它改规则」。

资产与前端现状：`web/src/features/rules/RulesPage.tsx`（现在只是只读卡片 + 启停开关）、`web/src/components/ui/*`（shadcn/Radix）。
